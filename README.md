A Manifest V3 extension for Chrome, Edge, and Firefox that converts American odds such as `-110`
and `+140` into implied probability. It watches live pages, so odds added or changed by sportsbooks
and single-page apps are converted as they update.

The extension is disabled globally after a fresh install. Open its toolbar popup to turn conversion
on for the current site. Live updates are enabled by default so dynamic sportsbook pages work as
soon as conversion is turned on.

> For more on implied probability and gambling odds, check out my [blog post](https://www.dannyhines.io/blog/betting-odds-extension).

## Features

- Live `MutationObserver` updates without replacing DOM elements or parsing page text as HTML
- Exact rollback when conversion is disabled
- Rounded explanatory (`+140 (42% implied)`), compact (`+140 (41.7%)`), and probability-only
  (`41.7%`) display modes
- Fixed readable precision and configurable longshot limits
- Per-site on/off rules stored locally; global display preferences sync through the browser profile
- Open shadow-root and related-frame support
- Accessible popup with live conversion count and a quick odds calculator
- Conservative parsing that avoids dates, phone numbers, percentages, CSS units, currency, and
  editable/code regions

The default append mode preserves the original odds. Implied probability includes the sportsbook's
vig and is not the same thing as a fair or no-vig probability.

## Development

Requirements: Chrome/Edge 119+, Firefox 128+, and Node.js 24.15+.

```sh
npm install
npm run check
```

`npm run check` runs strict TypeScript checking, the unit/DOM regression suite, clean production
builds for all three browsers, and browser-specific manifest validation.

To test an unpacked build:

- Chrome: open `chrome://extensions`, enable developer mode, and load `dist/chrome/`.
- Edge: open `edge://extensions`, enable developer mode, and load `dist/edge/`.
- Firefox: open `about:debugging#/runtime/this-firefox`, choose **Load Temporary Add-on**, and select
  `dist/firefox/manifest.json`.

To create all three store upload archives:

```sh
npm run package
```

This creates versioned ZIP files in `artifacts/` for Chrome, Edge, and Firefox, plus a source ZIP for
Mozilla's review of the minified production bundle. The command validates that each browser archive
has its manifest at the ZIP root and that the source archive contains the inputs needed to reproduce
the build. Chrome and Edge use the same Chromium manifest configuration but are packaged separately
for their respective stores. Firefox uses the same compiled JavaScript, HTML, CSS, and images with a
generated Firefox manifest. Its manifest declares a background script instead of a Chromium service
worker and includes a stable Gecko add-on ID for Mozilla signing.

If you're a Mozilla reviewer, you can reproduce the submitted Firefox ZIP from the source archive with:

```sh
npm ci
npm run build:firefox
npm run validate:firefox
```

Before submitting to AMO, run Mozilla's official linter (it may report newer manifest fields as
warnings when linting against an older schema):

```sh
npx web-ext lint --source-dir dist/firefox
```

## Multi-browser manifests

Shared manifest fields live in `config/manifest.base.json`. Small overrides in `config/manifests/`
contain only browser-family differences. Webpack generates the final manifest into each build; do
not edit a generated `dist/*/manifest.json` directly.

Useful individual commands are:

```sh
npm run build:chrome
npm run build:edge
npm run build:firefox
npm run validate:chrome
npm run validate:edge
npm run validate:firefox
```

## Architecture notes

The converter changes only existing `Text.data`, preserving text-node identity for React, Vue, and
other live-rendering frameworks. Each converted node records its original and rendered forms plus an
offset map. That lets the observer distinguish its own asynchronous mutations from site mutations,
reconcile partial updates, and remove only content generated by the extension.

Generated artifacts, dependencies, and release ZIPs are intentionally ignored. Source files,
tests, the base manifest and overrides, and `package-lock.json` are the reproducible project inputs.
